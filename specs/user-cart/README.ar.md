# سلة التسوق للمستخدم - دليل التوثيق

**الميزة**: user-cart  
**الإصدار**: 1.0  
**التاريخ**: 2024-10-29

## نظرة عامة

هذا المجلد يحتوي على التوثيق الكامل لميزة سلة التسوق للمستخدم. الميزة تنفذ نظام سلة تسوق مع قيد المتجر الواحد - يمكن للمستخدمين الاحتفاظ بمنتجات من متجر واحد فقط في سلتهم في وقت واحد.

  - فحص الدستور وهيكل المشروع

  - تتبع التقدم وحالة البوابات

  - تصميم نموذج البيانات (4 جداول)

  - العلاقات والمفاتيح الخارجية

  - 8 سيناريوهات المسار السعيد

  - 6 نقاط نهاية API موثقة بالكامل

## البدء السريع

### 1. قراءة المواصفات
ابدأ بـ `spec.md` (أو `spec.ar.md` للعربية) لفهم:
- ما تفعله الميزة
- قصص المستخدم ومعايير القبول
- المتطلبات الوظيفية وغير الوظيفية

### 2. مراجعة القرارات التقنية
اقرأ `research.md` لفهم:
- لماذا تم اختيار هيكل 4 جداول
- كيف يعمل قيد المتجر الواحد
- استراتيجية حساب السعر
- اعتبارات الأداء

### 3. فهم نموذج البيانات
راجع `data-model.md` للحصول على:
- تعريفات الجداول التفصيلية
- العلاقات والقيود
- قواعد التحقق
- صيغ حساب السعر

### 4. استكشاف عقود API
افتح `contracts/cart-api.yaml` لرؤية:
- جميع نقاط النهاية الـ 6
- تنسيقات الطلب/الاستجابة
- رموز حالة الخطأ
- أمثلة الحمولات

### 5. التحقق من التنفيذ
استخدم `quickstart.md` (أو `quickstart.ar.md`) لـ:
- اختبار جميع السيناريوهات الـ 8
- التحقق من حالة قاعدة البيانات
- فحص الأداء
- اختبار الترجمة

## القرارات الرئيسية

### قيد المتجر الواحد
- قيد فريد على `user_id` في جدول السلات
- التحقق على مستوى التطبيق قبل إضافة العناصر
- استجابة 409 Conflict عند اكتشاف عدم التطابق
- نقطة نهاية تأكيد منفصلة لاستبدال السلة

### هيكل البيانات
```
User (1) → Cart (1) → CartItems (N)
                         ↓
                    Options (N:M)
                    Addons (N:M)
```

### حساب السعر
```
سعر_العنصر = السعر_الأساسي + أسعار_الخيارات + أسعار_الإضافات
إجمالي_العنصر = سعر_العنصر × الكمية
إجمالي_السلة = مجموع(إجمالي_العنصر)
```

## نقاط نهاية API

1. **GET /api/user/cart** - الحصول على السلة الحالية
2. **POST /api/user/cart/items** - إضافة عنصر إلى السلة
3. **PUT /api/user/cart/items/{id}** - تحديث كمية العنصر
4. **DELETE /api/user/cart/items/{id}** - إزالة عنصر
5. **DELETE /api/user/cart** - مسح السلة بالكامل
6. **POST /api/user/cart/replace** - تأكيد استبدال السلة

## تدفق تبديل المتجر

```
1. المستخدم يضيف منتج من متجر ب
2. النظام يكتشف السلة الحالية من متجر أ
3. إرجاع 409 Conflict مع معلومات المتجر
4. المستخدم يؤكد عبر /cart/replace
5. حذف السلة القديمة
6. إنشاء سلة جديدة مع منتج من متجر ب
```

## نطاق التنفيذ

### قاعدة البيانات
- 4 ترحيلات (carts، cart_items، cart_item_options، cart_item_addons)
- مفاتيح خارجية مع حذف متتالي
- قيود فريدة لسلامة البيانات

### النماذج
- Cart - مع العلاقات وتسجيل النشاط
- CartItem - مع حساب السعر
- CartItemOption - جدول محوري للخيارات
- CartItemAddon - جدول محوري للإضافات

### المتحكم
- CartController مع 6 نقاط نهاية
- التحقق من الطلب
- منطق تعارض المتجر
- تكامل حساب السعر

### الاختبارات
- 8 اختبارات المسار السعيد
- 6 سيناريوهات التحقق
- اختبارات التكامل لجميع نقاط النهاية

## معايير الأداء

- **وقت الاستجابة**: < 500 مللي ثانية لجميع عمليات السلة
- **عدد الاستعلامات**: ≤ 3 استعلامات لاسترجاع السلة
- **التحميل المسبق**: استخدام `with()` لجميع العلاقات
- **الفهارس**: على جميع المفاتيح الخارجية

## الترجمة

- جميع أسماء وأوصاف المنتجات مترجمة
- أسماء وأوصاف المتاجر مترجمة
- أسماء الخيارات والإضافات مترجمة
- رسائل الخطأ ثنائية اللغة (EN/AR)
- استخدام LocalizationService الموجود

## تسجيل النشاط

الأحداث المسجلة:
- إنشاء السلة (مع store_id)
- إضافة العنصر (product_id، الكمية، الخيارات، الإضافات)
- تحديث الكمية (القديم → الجديد)
- إزالة العنصر (تفاصيل المنتج)
- مسح السلة (عدد العناصر، القيمة الإجمالية)
- استبدال السلة (المتجر القديم → المتجر الجديد)

## التبعيات

- Laravel 10.x

- Spatie Activity Log (لتسجيل التدقيق)
